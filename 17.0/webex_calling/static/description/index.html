Webex Calling Connector

Call records, caller matching and number lookup for Cisco Webex Calling — inside Odoo.

Import

A nightly job brings the call detail records of your Webex Calling organisation into Odoo. It continues from the last successful run, not from “today”.

Match

Every call is matched to a contact by phone number, trying the common spellings of the same number. Two contacts sharing one number produce no match — a confident wrong name is worse than none.

Look up

A token-protected endpoint answers “who is calling?” for a phone system or a screen-pop tool: name, company and a link to the contact. Nothing else.

Why this module exists

Cisco publishes the APIs. What decides whether an integration works or quietly loses data is a handful of facts that are hard to find. This module is mostly those facts, written down in code.

The trap What actually happens
720 hours Webex serves call data for 30 days and not one hour longer. A sync that has been broken for five weeks cannot be repaired afterwards. The import starts at the oldest day Cisco still serves and writes to the log how many days were lost.
invalid_scope Cisco rejects the entire authorisation if one requested scope is missing from your integration, and does not say which one. The connection form offers a fallback that authorises without queue names.
HTTP 451 Call data is served regionally. A European organisation asking the global endpoint is turned away. The client follows the address Cisco names in its answer.
12-hour window Any query wider than 12 hours is refused. The client slices the range itself.
One call, many rows A call through a hunt group writes one row per extension that rang. The import keeps the rows and marks which of them belong together.
Originating and terminating These describe the call leg, not the business direction. Swap them and every reachability figure built on top is inverted.

What it deliberately does not do

  • It never writes to Webex. Every requested scope is read-only.
  • It does not record audio and does not read message content.
  • It does not compute performance ratings for employees. Call counts say who reached how many customers, not who works well.
  • It needs no activation key and calls no service other than Cisco Webex.

Set up in five steps

  1. Create an integration in the Webex developer portal. Redirect URI: https://your-odoo/webex/callback — Cisco compares it character for character.
  2. Tick all five scopes on the integration: spark-admin:calling_cdr_read, spark-admin:locations_read, spark-admin:devices_read, spark-admin:people_read, spark-admin:telephony_config_read.
  3. In Control Hub, the account you authorise with needs administrator rights and, under Analytics, the role “Webex Calling CDR API Access”. A role only takes effect in a new token.
  4. In Odoo, open Webex Calling → Configuration → Webex connections, enter client id and secret and press Connect with Webex. The sign-in happens at Cisco; the Webex password is never asked for and never stored.
  5. Press Import now. The first import reaches back 30 days at most.

Good to know

  • Works on Odoo Community and Enterprise.
  • Depends only on base, mail and phone_validation.
  • One Python dependency: requests.
  • The lookup endpoint stays shut until you set its token.
  • Licensed LGPL-3, like Odoo itself. Free of charge.
  • Requires a Cisco Webex Calling organisation with administrator access.
